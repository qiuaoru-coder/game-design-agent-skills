# Eighteen gameplay relations: HOW loops form a network

Use these relations to label edges between gameplay loops or systems. Every edge must name its carrier, direction, receiving rule, and boundary. A shared theme, UI link, or simultaneous existence is not a gameplay relation by itself.

## Resource relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 双向推动 | A → B; B → A | reciprocal growth and positive feedback | Does each output materially alter the other system? | Too strong runs away; too weak feels decorative. |
| 争夺 | A ← R → B | opportunity cost around a finite resource | Does choosing A force B to wait or lose something? | Fake scarcity adds chores without tradeoffs. |
| 转化 | A → B → C | production or value chain across identities | Does every conversion change use, value, or future choice? | Renaming without functional change is cosmetic. |

## Information relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 反馈 | 行动 → 结果 → 修正 | learning and control | Can the player read the result and change the next action? | Delayed or ambiguous feedback breaks learning. |
| 汇聚 | a + b + c → conclusion | combine fragments into a cognitive leap | Is each clue useful alone and more meaningful together? | Collection without a new conclusion is busywork. |
| 干扰 | truth + noise + decoy | risky judgment under uncertainty | Can players distinguish signals through evidence rather than pure guessing? | Unverifiable noise feels arbitrary. |

## Spatial relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 辐射 | center → surroundings | make a key point alter surrounding rules | Which nearby rules change when control changes? | Radius too broad flattens the map; too small lacks value. |
| 阻滞 | many inputs → narrow output | create bottlenecks, queues, detours, or expansion choices | Can congestion be predicted, relieved, or exploited? | Waiting without counterplay is dead time. |
| 塑形 | map → rewired map | let players rewrite future action space | Does modification persistently change routes, visibility, or flow? | Cosmetic terrain editing is not shaping. |

## Action relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 续航 | input → operation | turn continued operation into resource management | Why does it stop, and is replenishment a tradeoff? | Fine-grained upkeep becomes repetitive labor. |
| 轮转 | A → B → C → A | make order and timing strategically valuable | Can order be predicted, altered, or exploited? | If timing never changes outcomes, it is only waiting. |
| 改写 | old rule → new rule | change how the system behaves, not only its values | Does player behavior change or are numbers merely larger? | Too many rewrites make the system unreadable. |

## Cost relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 转嫁 | A's cost → B | shift who or when bears a cost | Is the cost still traceable after transfer? | Hidden destination looks like cost removal. |
| 反作用 | expansion ↑ → pressure ↑ | attach new management pressure to advantage | What burden grows with player power? | Pure numerical catch-up erases accomplishment. |
| 恢复 | main path fails → backup takes over | reconnect play after failure | Does recovery retain a meaningful cost? | Cheap recovery removes failure stakes. |

## Result relations

| Relation | Structure | System value | Check | Failure risk |
|---|---|---|---|---|
| 分化 | common start → distinct branches | produce builds, identities, or play styles | Do branches change play rather than color or magnitude? | Routes reconverge on one answer and create false choice. |
| 共振 | A + B + C → amplified result | create qualitative synergy | Does the combination change decisions beyond simple addition? | Hidden triggers prevent deliberate pursuit. |
| 传导 | local change → network → global effect | propagate local consequences through the game | Through which nodes does it spread, decay, or amplify? | Unbounded chains make causality uncontrollable. |

## Network construction

1. Treat each major loop or system as a node.
2. For every proposed edge, label relation, carrier, direction, trigger, and receiver effect.
3. Keep only edges that change decisions or state in the receiving system.
4. Mark feedback polarity and possible runaway, deadlock, starvation, opacity, or cascading failure.
5. Define attenuation, caps, delays, reset points, or player counterplay where needed.
6. Check both directions when claiming reciprocity; a one-way input is not 双向推动 or 传送门模式.

## Audit failures

- **Decorative link**: systems share fiction or UI but no state travels.
- **Carrier missing**: an arrow is drawn without naming what moves.
- **Receiver missing**: an output arrives but no rule reads it.
- **Fake scarcity**: multiple systems display the same resource but choices do not exclude each other.
- **Unbounded positive feedback**: reciprocal growth lacks caps, cost, opposition, or reset.
- **Opaque propagation**: distant consequences cannot be traced through intermediate nodes.
- **Redundant systems**: two nodes produce equivalent decisions and should be merged or differentiated.
