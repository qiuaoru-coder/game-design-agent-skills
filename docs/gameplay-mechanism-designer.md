# 玩法机制设计器：大白话使用说明

## 它是做什么的？

这是一个帮助你设计游戏玩法的 Codex Skill。

你不需要懂专业的游戏机制理论，只要给它一个关键词、道具、角色、画面、机制或者一句游戏灵感，它就能把这个想法扩展成几个结构不同的玩法方向。

如果你的想法已经比较具体，它还可以继续补齐玩家目标、核心操作、规则、失败条件、奖励、成长、核心循环和系统联动。如果准备做原型，也可以让它输出状态机、初始参数、制作范围、开发顺序和测试方案。

它还可以反过来检查已有策划案，找出“只有功能、没有玩法”“循环没有闭合”“几个系统互不相关”等问题。

简单地说：它能帮助你把一句灵感，逐步变成一套更完整、更容易制作和验证的游戏玩法方案。

## 常规用法

### 1. 从一个灵感生成玩法

输入关键词、道具、角色、场景、画面或一句设定，让它给出三个真正不同的玩法方向，而不是只换题材。

```text
使用 $gameplay-mechanism-designer：

一把会记住历任主人的钥匙。
请给我三个不同的玩法方向，并推荐一个。
```

### 2. 把模糊想法补完整

已经有大概玩法时，让它补齐玩家目标、核心决策、规则、失败、奖励、成长和内容结构。

```text
使用 $gameplay-mechanism-designer：

我想做一个“玩家带着会吸引怪物的宝物逃跑”的游戏，
但目前只有这个概念。请把它扩展成完整玩法。
```

### 3. 设计核心循环

适合“这个功能能运行，但不知道玩家为什么会继续玩”的情况。

```text
使用 $gameplay-mechanism-designer：

玩家探索遗迹、收集零件、修复飞船。
请把这几个行为设计成有风险和取舍的核心循环。
```

### 4. 设计系统联动

把战斗、探索、建造、经济、成长等系统真正连接起来。

```text
使用 $gameplay-mechanism-designer：

我有探索、采集、建造和防守四个系统，
但它们像四个互不相关的功能。
请重新设计核心循环和系统关系，并指出应该删除什么。
```

### 5. 生成完整玩法方案

可以要求输出目标玩家、体验目标、核心决策、机制链、循环、内容、成长、反馈和风险。

### 6. 生成原型方案

可以继续输出灰盒范围、状态机、参数、实现顺序、删减清单、测试方法和验证指标。

```text
使用 $gameplay-mechanism-designer：

种子：玩家只能通过改变影子的方向移动本体
体验目标：先困惑，随后产生空间顿悟
形式：PC单人、2D横版、键鼠
约束：1名程序、1名美术、Godot、两周
输出：10分钟灰盒原型、状态机、参数表和测试计划
```

### 7. 改造已有机制

让它给机制增加条件、代价、分支、循环，或者把机制放到角色、地图、流程、规则和局外成长等不同层级。

### 8. 审查策划案

粘贴已有方案，让它检查目标、状态变化、机制链、循环、系统关系和制作风险，并给出修改优先级。

## 推荐输入格式

只给一句灵感也可以使用。想让结果更集中，最好提供下面五项：

```text
使用 $gameplay-mechanism-designer：

种子／不可改变的核心灵感：
玩家要完成什么：
希望玩家有什么体验：
游戏形式：平台、视角、单人或多人
希望得到：玩法方向／完整方案／系统设计／原型方案／策划案审查
```

如果已经进入制作阶段，还可以补充：

```text
目标玩家和参考游戏：
单局时长和长期结构：
必须包含／绝对不要：
团队人数、引擎、时间和内容预算：
商业化或长线运营限制：
```

## 使用提醒

- 信息不完整也可以开始，Skill 会说明关键假设。
- 输入越明确，结果通常越贴近你的目标和制作条件。
- 它能提高设计完整度和可执行性，但不能保证玩法一定好玩。
- 市场判断、数值平衡、内容量和最终体验仍然需要竞品研究、原型和真人试玩验证。
